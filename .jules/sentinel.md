## 2025-02-18 - [CRITICAL] Firestore Path Traversal
**Vulnerability:** The `quickAddHabit` Cloud Function accepted a `habitId` parameter without validating it against Firestore ID constraints. This allowed a path traversal attack where an attacker could supply `../../members/targetUser` to read/modify arbitrary documents in the household collection, bypassing the intended collection scope.
**Learning:** Admin SDK in Cloud Functions bypasses `firestore.rules`. Unlike client-side SDKs where rules enforce paths, server-side code MUST manually validate all path components derived from user input to prevent traversal and unauthorized access.
**Prevention:** Always validate document IDs using a strict allowlist regex (e.g., `^[a-zA-Z0-9_-]+$`) before using them in `db.doc()` or `db.collection()` paths. Never trust user input in file or database paths.
